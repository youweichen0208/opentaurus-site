Capability Probe

先探测，再决定暴露什么工具

不要把所有 TaurusDB 特性硬编码成静态卖点。更好的展示方式是让用户看到：不同内核、不同实例能力下，工具集会发生变化。

建议后续补一张真实截图：Claude 或其他 Agent 调用 `list_taurus_features` 后返回结果。

Execute SQL

把 SQL 执行样例单独展示

你现在缺的不是更多 CLI 文字，而是一个真实的 MCP 样例：Agent 发起 SQL 执行，MCP 返回结构化结果、行数、耗时、风险边界。

execute sql
tool> execute_sql("select count(*) from orders;")
rows: 1
latency_ms: 18
result: [{"count(*)": 241905}]
Diagnostics

诊断结果要展示“结论 + 下一步”

慢 SQL、锁、连接堆积不是简单列表。更适合展示的是：`diagnose_service_latency` 给出根因摘要，并指向下一步工具。

diagnostics
severity: high
summary: slow SQL plus connection buildup
next: diagnose_slow_query / show_processlist
