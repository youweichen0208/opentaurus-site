三个入口，同一条证据链

网站不应该把 OpenTaurus 讲成“另一个 DB CLI”，而是把它讲清楚：MCP 是主工具面，CLI 是 companion，Cloud evidence 是诊断深度来源。

MCP Tools

给 AI 客户端的原子工具面

适合 Claude Desktop、Cursor、VS Code。按 capability 动态暴露 TaurusDB 特性，并保持统一 response envelope。

tools:
get_kernel_info
list_taurus_features
diagnose_service_latency
flashback_query
Companion CLI

不给你第二个 SQL 客户端

CLI 负责 `init`、`doctor`、`smoke`、`mcp call`、`runbook` 和 `context export`。它验证和编排真实 MCP，而不是重复执行数据面动作。

taurusdb> mcp tools
taurusdb> mcp call diagnose_service_latency
taurusdb> runbook latency
Cloud Evidence

把 CES / DAS 接到同一套诊断里

云侧实例解析、Cloud Eye 指标和 DAS 慢 SQL 不再散落在脚本里，而是进入同一套 diagnostics contract。

taurusdb> cloud validate
instance_id: taurus-001
metrics: CES ok
slow-sql: DAS partial

从 capability probe 到 runbook report

版式沿用 OpenDB 的终端主导风格，但叙事改成 OpenTaurus 的强项：TaurusDB 特性显隐、evidence-backed diagnostics、MCP/CLI 协同。

Capability-Aware

TaurusDB 能力按内核自动显隐

`get_kernel_info`、`list_taurus_features`、`explain_sql_enhanced`、`flashback_query` 不应该平铺成静态卖点。页面上要明确传达：OpenTaurus 会先探测内核，再决定暴露什么工具和什么建议。

Diagnostics

慢 SQL、锁、连接、复制、存储走同一套 evidence contract

这一段应该学参考站的“终端截图 + 结论 + 数字”，但不能停留在通用数据库故事。 OpenTaurus 更值得展示的是：`diagnose_service_latency` 如何串 slow SQL、lock waits、processlist 和 CES 指标。

Companion CLI

CLI 不重复执行，它验证和编排真实 MCP

这是 OpenTaurus 网站最该讲清楚的差异点。CLI 不是 `sql run` 的营销壳，而是 `mcp tools`、`mcp call`、`mcp smoke`、`runbook latency`、`context export` 的本地协同层。

stdio 嵌入式 MCP client
Smoke CI / 联调 / 验收入口
Runbook 对人类更友好的编排
taurusdb runbook latency
taurusdb> runbook latency --since 15m --report latency.md
calls: diagnose_service_latency -> find_top_slow_sql -> show_processlist
✓ report generated latency.md
next: open report in Cursor / Claude and continue from context block
Cloud Evidence

从 cloud validate 到 context export，联调和交付都更稳

OpenDB 的页面后半段强调 sentinel 和 AI 深度诊断。对 OpenTaurus，更贴近你当前阶段的卖点应该是： 云侧证据源可验证、配置可导出、上下文可复用。

CASE 01 / BASELINE

MCP smoke 打通基础链路

这个案例用于证明：实例可连、MCP 可启动、tool 注册正常、capability probe 有真实返回。

  • 症状：初次接入，需要确认最小链路可用
  • 证据：`mcp smoke`、`tools/list`、默认 datasource probe
  • 修复：补 profile、权限或 client config
  • 验证：再次 smoke 全绿
tool> diagnose_service_latency(15m)
severity: high
summary: slow SQL + connection buildup
next: diagnose_slow_query
      show_processlist
CASE 02 / DIAGNOSTICS

服务变慢时给出可继续下钻的结论

这个案例用于展示 diagnostics 不是只报现象，而是会把 slow SQL、连接堆积和下一步建议串起来。

  • 症状：接口超时、CPU 高或响应变慢
  • 证据：slow SQL、processlist、CES 连接或存储指标
  • 修复：继续下钻 SQL、索引、锁或连接源头
  • 验证：修复后重跑 runbook / diagnose
taurusdb> cloud validate --profile prod-ro
✓ instance resolved
✓ CES metrics ok
⚑ DAS full-sql partial
✓ context export ready
CASE 03 / CLOUD

云侧 evidence 源验证与脱敏导出

这个案例用于展示你不是只会本地 MySQL 诊断，而是能把 TaurusDB 云侧实例、CES、DAS 和 context export 接起来。

  • 症状：云端联调、证据源权限或配置不确定
  • 证据：instance resolver、project/node、CES、DAS
  • 修复：调整 region、AK/SK、instance_id、node_id、权限
  • 验证：`cloud validate` 通过并生成 export
